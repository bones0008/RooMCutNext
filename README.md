# RooMCutNext

**Android 原生单层时间线视频剪辑器** — Kotlin + Jetpack Compose + Media3。

**[中文](README.md)** | [English](README.en.md)

从一个空项目到能导出 MP4 的完整剪辑工具：导入素材 → 时间线排列 → 精确剪辑 → 预览 → 导出。

## 功能清单

对照 V1 需求清单逐条实现（✅ = 已实现，⚠️ = 简化实现，❌ = 留待后续版本）：

### 〇、项目管理（首页）
- ✅ 项目卡片封面 = **时间线第 20 帧自动抓取**（v1.0.11）：回到项目列表时自动刷新，剪辑/调序/变速后封面跟着变（选第 20 帧是因为片头第 1 帧常常是黑场）；空时间线 / 纯音频 / 提取失败的项目回退到影片图标
- ✅ 新建项目两步走（v1.0.11）：先选横屏/竖屏 → 再输入项目名称（可修改；留空或直接「创建」则用默认「项目 N」）
- ✅ 重命名 / 复制项目 / 删除（确认弹窗）/ 按最近编辑排序
- ✅ 应用图标更新（v1.0.11）：黑底 + 蓝色播放箭头（去掉了旧版的斜杠）

### 一、素材管理
- ✅ **素材库（v1.6.13）**：导入即入库——「添加素材」选中的文件完整拷进项目素材库，面板自动弹出展示全部素材（缩略图 / 时长 / 分辨率 / 已用次数）；**点击素材即上时间线**（视频/图片追加到末尾、音频落到播放头），「全部添加到时间线」一键上轨；未使用的素材可删除（连同源文件）；对齐桌面剪辑软件"素材箱 → 拖上时间线"的标准工作流，也为 AI 选材提供完整视野；**v1.6.15 起素材库是唯一素材入口**——独立的「添加素材」按钮已删（用户反馈两个入口重复多此一举），导入走素材库面板顶部「导入素材（可多选）」行（系统选择器列表滚动多选，视频/照片/图片/音乐全收），空时间线的大 ＋ 也改为直接打开素材库
- ✅ 系统相册选择视频/图片（Photo Picker，支持多选）
- ✅ 文件管理器选择（SAF，支持 MKV / WebM 等更多格式）
- ✅ MP4 / MOV / MKV / WebM（取决于设备解码器）+ JPG / PNG / WebP / HEIC
- ✅ 图片作为独立时间线 Clip（默认 3 秒，可拉伸到 60 秒）
- ✅ 素材信息：分辨率 / FPS / 时长 / 编码 / 音频 / 文件大小（「信息」面板）
- ✅ 导入即复制到应用私有目录（杜绝 URI 权限过期导致项目损坏）

### 二、单层时间线（核心）
- ✅ 添加 / 删除 / 拖动排序 / 点选 / 高亮 / 时长显示
- ✅ 时间标尺（自适应刻度，**正常缩放下 5 秒一个数字**（v1.0.9）；缩小拉远自动拉长到 10/15/30s，放大到细看时回落到秒级保证修剪有参照）
- ✅ **固定播放头 + 时间线滚动（LibreCut 式，v1.0.4）**：播放头固定在时间线中央，播放时素材从右往左移动；拖动时间线任意空白区域即为刮擦（scrub），画面实时跟随
- ✅ **点空白处取消选中（v1.0.5）**：点按标尺/空白区域不再跳转时间线，只清除选中；定位仅靠按住拖动
- ✅ 双指捏合缩放（6~480 px/s，播放头锚定）+ 缩放按钮 + 一键适配
- ✅ 拖动片段自由摆放（v1.0.9）：拖到哪里落哪里，可留黑场空隙；插入位置实时预览 + 触觉反馈
- ✅ **时间线固定高度 + 垂直滚动（v1.5.4）**：轨道栈改为**底部锚定** —— 视频轨/音频轨钉在时间线区域底部，文字/画中画层向上生长，加多少层都不会把视频轨挤到工具栏底下（竖屏项目旧版只能容 2 个文字层 + 1 画中画 + 视频 + 音频，超出即被裁剪）；层数堆高超过可视区时自动变为可垂直滚动（上下拖动空白区/轨道背景滚动，手指上滑看下方内容），标尺钉在顶部不随滚动；选中/新增的层不在视野内时自动最小滚动使其可见；时间线总高度横竖屏项目均固定不变。垂直布局数学（区域几何/锚定/滚动钳制/选中揭示）抽为纯函数并钉进单测
- ✅ **转场预览流畅度三连修（v1.5.5）**：转场头层播放器改为**会话级常驻**（media3 播放列表模式原地换效果链，复用同一 EGL 上下文与已编译 shader，换窗不再销毁/重建整套管线——这既消除每个转场结束时的心跳卡顿，也止住多次播放后的累积变卡）；转场尾段淡出改为**逐帧插值**（原来按 33ms 同步节拍阶梯式降 alpha，观感即"结束跳帧"）；尾段期间头层**音频同步衰减**（消除边界处与主体画布双声道重叠的短促回声）
- ✅ **转场收尾"活画面"尾段（v1.5.6）**：头层预览素材在转场窗口结束后**继续多播一段尾段时长**（600ms+余量），收尾淡出期间淡的是 B 段的**实时画面**而非冻结帧——旧版冻结帧与底下主体最多拉开 400ms 内容差，淡出收尾观感即"跳帧"；现两层内容差被压缩到主体渲染延迟（1-2 帧），收尾平滑由构造保证（转场 shader 进度已钉在 p≥1 输出全不透明 B，导出不受影响）。同时修复 v1.5.5 常驻播放器复用 TextureView 的**残影闪现**（无预挂载余量的入窗会短暂全屏显示上一窗口末帧，现首帧渲染前保持透明）；尾段改为 600ms 纯掩蔽增益；尾段音频改为边界处**硬切静音**（主体 B 段音频全量接管，消除梳状回声）；DIAG 浮层新增头层挂载→首帧延迟读数，便于真机排查"越播越卡"
- ✅ **转场预览"越播越卡"四层根治（v1.5.7）**：真机复测（DIAG 读数头层挂载→首帧延迟高达 16474ms）定位到 media3 1.11.1 输入流切换机制的累积损伤，四层修复：①**stop 前清扫**——重定向头层播放器前先做同位置 seek，强制 videoSink.flush 把管线内在途帧全部清空（旧版 stop() 会把未渲染帧绞杀在输出队列里，新时钟拒绝释放它们，延迟逐次滚雪球到 16 秒级，这就是"下一段直接出现然后静止"）；②**延尽门控**——在途内容未排空前推迟重定向（素材尾段延长量同时按下一转场窗口几何封顶，短片段不再被中途打断）；③**特效链值稳定**——样式/进度本就是逐帧 uniform，改为单个会话级可变实例原地更新窗口参数，media3 的链比较不再触发"释放+重编译整条 shader 链"风暴（旧版每次重定向要编译两遍）；④**有界回收**——常驻播放器每服务 12 个转场窗口就安全重建一次，对 media3 自身的采样 shader 释放竞态（官方 TODO b/417680219）兜底，累积损伤从此有硬上限
- ✅ **重播回穿重挂载（v1.5.8）**：v1.5.7 复测（连播 7 次，DIAG 首帧读数涨到 46984ms；第二段画面第 2 次在转场开头短暂停留、第 4 次直接出现在半程位置静止、第 7 次占到 5/7 画面直到快收尾才动一下）把真凶钉死在一处状态机漏洞：**重播时"规格未变即早退"的热路径把头层原样留给了新一轮播放**，v1.5.7 的整套重定向卫生设施根本没参与——上一轮残留的播放器位置（窗口末+尾段延长）在入窗瞬间被超前漂移策略误判为"跑得太快"而**自我停泊**（整窗几乎无新帧 = "静止"，停泊时长随残留位置逐轮加深）；残留的 firstFrame 标志骗过首帧透明门控，复用 TextureView 当场亮出上一轮残影（= "B 段直接出现"）；挂载时钟从未重挂，DIAG 读数实为"距首次挂载的总会话时长"伪指标（≈播放次数×单次时长，这就是 46984ms 的由来）。修复：每次挂载记录**播放头高水位**，高水位越过窗口末而当前播放头又回到窗口前/内（重播/循环/播放中回跳）即判定"回穿"，强制走完整重定向（stop 前清扫 + 位置归零 + 全部标志重挂，重播后与首次播放完全同构）；暂停刮擦保持原紧致逐帧追踪不变；判定抽为纯函数并钉 5 项新单测
- ✅ **主体换段开销门控掩蔽（v1.5.9）**：重播劣化修复后残留的"每一次（含首次）转场收尾跳帧"定位到主体播放器（CompositionPlayer）的 **item 边界切换固有开销**：换段期间新片段解码器重初始化，表面仍显示**旧片段末帧**，而播放器上报的位置（以及尾段淡出的 alpha）却照常推进——头层于是把 B 段实时画面淡在**过期的 A 段残影**上：alpha 越降渗透越重，主体新段首帧到达时弹入即跳帧。修复：转场尾段改为**主体存活门控**（body-live gate）——以主体 `onRenderedFirstFrame`（media3 逐 item 边界触发，源码级验证）为信号，等待期掩蔽层**全不透明**（覆盖到主体真正显示出新段为止），其后才在 250ms 内淡出，淡的始终是"活的 B 叠活的 B"；等待上限 600ms（超时优雅揭示，不再无限遮盖坏死的主体）；尾段中途回暂停/恢复可无损续走（锁存器与位置域调度同构）；DIAG 新增 `tail body-live +Nms` 读数直读换段真实耗时、`tail body-live TIMEOUT` 标记超时路径。门控数学抽为纯函数并钉 9 项新单测（含"揭示时长 ≤ 素材尾段延长量"构造不变量）
- ✅ **音频导入落点在播放头（v1.5.5）**：导入音频不再追加到时间线末尾，而是从播放头位置起插入（可与既有音频重叠，轨道自动分道；多选时依次排开）；**转场面板移除缩放**（真机反馈该效果无反应，且缩放属于素材收尾效果而非转场；枚举保留旧项目兼容，面板不再可选）
- ✅ **播放卡死自愈看门狗（v1.6.0）**：针对真机偶发的"播放中画面冻结、必须手动拖一下时间线才能继续"（media3 stuck-playing 失败模式：isPlaying=true 而位置不再推进），33Hz 播放轮询内置看门狗——位置冻结超过 1.5s 自动执行与"手动拖动"完全等价的同位置 seek 解围（4s 冷却防抖），两发无效自动升级为 pause→seek→play 全管道复位；全部事件进 DIAG 浮层（连点标题 5 次可见 `STALL` 行，含冻结时长/状态/次数），阈值对 0.25x 慢速播放安全（1.5s 窗口内仍推进 375ms，远高于 5ms 判定线）

### 二·五、AI 剪辑助手（v1.6.0 → v1.6.9）
- ✅ **对话式 AI 剪辑（OpenChatCut 模式复刻）**：用一句话描述想要的剪辑，agent 通过工具调用直接在时间线上执行**真实编辑**——分割 / 删除 / 排序 / 修剪 / **恢复原长（v1.6.12）** / 变速 / 音量 / 滤镜(LUT) / 转场 / **黑场插入（v1.6.1）** / **素材库上时间线（v1.6.13）** / 文字字幕 / 音频调整 / **希区柯克变焦（v1.6.21）** / 跳转共 22 个工具，与手动编辑共享同一套 TimelineOps 核心命令（agent 与编辑器本体操作同一个"EditorCore"，不存在第二套会漂移的编辑语义）
- ✅ **对话面板布局重做（v1.6.2，真机反馈）**：打开 AI 面板时不再显示"AI 剪辑 + 关闭"头部行和底部工具栏（对话中用不到，纯浪费空间）——聊天区自动变大，关闭键收进输入行右侧；键盘弹出时**只压缩对话区、预览画面保持原尺寸**（旧版会把整个界面连同视频一起压扁，收起键盘后视频还停在缩小状态、必须点一下播放才恢复）；引导卡与提案卡进入消息流可滚动，输入行固定在底部永远可见；发送键改为恒可见配色（旧版空文本时是几乎看不见的禁用灰色）
- ✅ **直接执行 + 单步撤销（v1.6.4，真机反馈）**：AI 改完直接写入时间线，不再弹提案卡确认（真机反馈"为什么要弹出对话框确认？直接做就好了"）——整组修改作为**一条撤销记录**提交，不满意一键撤销整组 AI 操作；面板逐条通俗汇报做了什么，agent 可附带 seek 到修改观察位，改完播放头直接落到改动处
- ✅ **BYOK 自带密钥（本地优先）**：支持智谱 GLM / DeepSeek / Kimi / OpenAI 及任意 OpenAI 兼容端点（含局域网 Ollama / LM Studio）；API Key 只存本机；对话只发送时间线结构（素材名 / 时长 / 轨道 / 播放头），开启画面理解时另附每段一张 384px 小图（v1.6.6），切到"整段视频"档则另发压缩后的 480p 小视频代理（v1.6.9），均不发送原始媒体文件
- ✅ **播放中删空素材的传输修复（v1.6.16，真机反馈）**：播放预览时把时间线上最后的素材删掉，旧版会**继续播放已删除的画面且暂停键完全失效**（空时间线的暂停按钮是无操作，播放器又从未被停过）；现在删空素材即真正停止传输——暂停 + 播放器回到 IDLE 清掉残留合成与末帧，播放/暂停状态与播放头归零复位，下次导入从 0 开始干净起播
- ✅ **AI 对话语音输入（v1.6.14）**：输入框右端内嵌麦克风 —— 点一下开始说（实时上屏），说完再点一下落定，扫一眼、改两个字照常发送；**不自动发送**，防“听岔了直接执行错误剪辑指令”；系统 SpeechRecognizer 引擎（在线优先 / 无 GMS 的 ROM 退离线引擎 / 两者皆无则隐藏按钮干净降级），零新增依赖零费用，音频只经系统识别器流转不落盘不上传，识别语言跟随 APP 界面语言；**v1.6.16 升级**——麦克风移出输入框成为独立常驻按钮（无语音识别服务的 ROM 也可见，点按给出解释与替代方案，不再"找不到麦克风"），AI 底栏紧凑化（输入行高度约降三分之一：40dp 紧凑输入框 + 12sp 小字号占位文字，技能入口改竖排胶囊更省宽度）；**v1.6.17 修复**——40dp 硬限高会压缩 M3 输入框内部布局、正文被纵向裁切“只能看到一半”，且单行模式长文本永远看不全；输入框重写为多行自适应：高度永远跟随内容（1 行约 48dp 紧凑起跳、随文字自动长高、最多 5 行封顶后框内滚动），任何字号缩放下都不再裁字，Enter=换行可写多行剪辑指令
- ✅ **时间线永无空隙（v1.6.18，真机反馈）**：拖动素材永远只改变顺序——松手即紧贴落位，不再拖出空白区域；黑底停顿只能通过显式「加黑场」插入（素材前/后，可拉伸可删除）。旧版本拖出的间隙在打开项目时一次性转换成等时长的黑场素材（播放结果完全不变，但从此可见可管理）；超 60s 的间隙自动分段拼接，不足 0.1s 的零头直接抹掉；**黑场位置修复**——「在素材前添加/在素材后添加」自首版起前后颠倒（选“前”黑场却落到素材后面、选“后”却跑到前面），现已归位并加回归测试钉死；**v1.6.19 为同内容重发**——黑场修复曾一度以同号 v1.6.18 换发，但 Android 同版本号无法覆盖安装（装过任一 v1.6.18 构建请直接升 v1.6.19，versionCode 65 干净覆盖升级，项目数据不受影响）

- ✅ 实现方式：前段全程不透明垫底，后段头部以自定义 GL shader（时间驱动的逐像素 alpha/色彩）完成转场——无黑闪、无双重半透明叠加问题；预览与导出挂载**同一个** TransitionEffect shader，所见即所得
- ✅ **v1.5.1 修复「预览全是叠化」**：同一 shader 的输出在两条管线的 alpha 合成约定不同——导出走 DefaultVideoCompositor（`GL_SRC_ALPHA` 直通混合），预览 head 播放器直接写 TextureView 的 SurfaceTexture（Android 按**预乘 alpha** 合成）。v1.5.0 输出直通 alpha，被预览侧误读成 `rgb + (1−α)·底`，导致所有位置不动的转场（闪白/时钟擦除/擦除/缩放…）在时间线上全部退化成同一种"鬼影叠化"。现在预览挂载点按预乘约定输出（`rgb·α`），导出侧保持直通不变
- ✅ **v1.5.2 修复「播放经过的转场仍全是叠化 + 删除转场画面残留」**：v1.5.1 的预乘修复方向正确，但在受影响的设备上 shader 根本没挂载成功——预览控制器的降级机制被两处状态机缺陷打穿：
  - **首帧标志被预卷期反复擦除**：driveHead 的出窗早退分支每个 sync tick（约 33ms）都重置首帧标志，预卷里按时渲染的首帧进窗口前就被抹掉；而降级宽限检查只在窗口内运行，于是一进窗口必然判定"从未渲染"
  - **宽限 450ms > 预卷 400ms 的算术矛盾**：注释声称降级"落在预卷期内不可见"，实际落在进窗口后 50ms 处，恰好触发注释里描述要避免的"淡入中段闪屏重建"
  - 两者叠加：播放经过转场（而非直接跳进窗口）时，会话级降级几乎必然触发，所有样式退化为视图层叠化渐变；直接拖动进窗口的路径恰好躲过重置，所以 bug 呈现"位置相关"的假象
  - 修复：首帧标志生命周期收敛为"挂载时置 false、渲染即置 true、期间任何代码不得触碰"；宽限拆成冷/热两档（会话首个 effects 挂载 2500ms——覆盖 EGL 上下文 + shader 编译 + 解码器冷启动；之后 1200ms）；预卷 400→600ms；数值不变式钉进 HeadEffectsPolicy 单测（防止 v1.2.8 式的"注释与算术矛盾"再度回归）
  - **删除转场残留**（同版本修复）：reconcileHead 此前对"播放头不在任何窗口"的已挂载 head 只隐藏不释放，而 driveHead 在同一 sync tick 里按**过期**的 spec 再把 alpha 拉回 1——删除转场后每拍"先藏后复活"，直到退出项目重进才恢复。现在挂载的 spec 一旦从当前 spec 列表消失（转场被删，或样式/时长/静音/音量被改）就彻底释放播放器；仅字节级相同的 spec 保留"隐藏待复用"的拖动优化
- ✅ **v1.5.3 修复真机反馈的五组预览症状**（源码级求证根因后修复）：
  - **转场时间底部亮线（下滑入/下擦除免疫）**：叠加层内容矩形比 PlayerView 视频表面矮 1px — media3 的 AspectRatioFrameLayout 有 1% 形变容差（宽高比差≤1%时视频铺满整个视图），而旧布局代码无条件截断取整，头部矩形矮一行漏出旧片段画面。现 CanvasFitMath 逐分支复刻库行为（含容差带），头部像素级覆盖底层视频
  - **卡顿 + 首播闪黑（需连播 7-8 次才流畅）**：冷管线（解码器 + EGL + shader 编译）落在 600ms 预卷内完不成。现播放中提前 2.5 秒预挂载下个窗口的 head，停车位完成预热再进窗；预挂载顺带预热入段解码器，软化窗口末尾 body 的跨片段切换（闪黑的另一半）
  - **圆形/时钟效果做到一半突然消失直接显示第二段**：双时钟漂移 — body 停顿时 head 继续走，提前到达终点停在满屏 B；ENDED 回绕无冷却造成逐拍 seek 风暴。现引入时钟转向（超前 80ms 速度修剪、500ms 停车）+ 回绕冷却

## 安装 APK

最简单的方式（无需任何开发环境）：

1. 打开本仓库的 [Releases](https://github.com/bones0008/RooMCutNext/releases) 页面，进入最新版本（当前为 **v1.6.9**），下载 `app-release.apk`
2. 把 APK 传到手机（微信/网盘/USB 均可）
3. 在手机上点开该文件，系统询问「允许安装未知来源应用」时选择允许
4. 安装完成，桌面出现「RooMCutNext」图标

> 签名密钥不随仓库分发（密钥材料永不入库）：官方 Release APK 使用仓库外保存的密钥签名。
> v1.6.x 官方 APK **仍使用原签名密钥**（密钥轮换推迟到上架应用商店前执行），从 v1.5.x 官方 APK 直接覆盖升级，项目数据无损；从 v1.0.4 及更早版本升级需先卸载（一次性）。轮换执行时会在 Release 说明中显著标注（届时需一次性卸载重装）。
> 从源码自建：clone 后 debug 构建开箱即用；release 签名在 `local.properties`（git 忽略）配置 `roocmcut.keystore` / `roocmcut.storePassword`，或环境变量 `ROOCMCUT_KEYSTORE` / `ROOCMCUT_STORE_PASSWORD`，未配置时自动回退 debug 签名。

**系统要求：Android 12（API 31）及以上。**

> v1.6.0 起启用 R8 代码压缩：安装包从 56MB 瘦身到 **12.8MB（-77%）**，功能与内置资源零删减——5 款文字字体与 8 款 LUT 滤镜全部保留（此前的体积大头是未裁剪的依赖代码：material-icons-extended 等整包打入）。

### 帧率策略

针对 30FPS 手机素材 + 24FPS AI 生成素材的混合场景：

1. **项目帧率**：首个导入视频的帧率自动吸附到 24/25/30/50/60（AI 视频 24FPS 的项目就是 24FPS 项目）
2. **帧步进**：播放头位于哪个片段，就按**该片段源帧率**步进（在 30FPS 项目里步进 24FPS 的 AI 片段 = 每次 1/24 秒）
3. **修剪对齐**：Trim/Split 的边界吸附到**源文件帧网格**，不产生重复帧或丢帧
4. **导出**：各片段保持原生时间戳（VFR），24 与 30 混排互不干扰，避免强制重采样造成的抖动

## 已知限制

1. **转场（Crossfade 等）** 未实现 — 如需求文档所述，转场会引入多层合成架构，计划 V2 做复合层
2. ~~音频独立轨道未实现~~ → **v1.0.4 已实现**：独立音频轨（导入 MP3/AAC/WAV/FLAC/OGG 等，多轨混音、拖动/修剪/音量/淡入淡出）
3. **导出为 VFR**（可变帧率）MP4 — 所有主流播放器/平台都支持，但某些严格 CFR 的工具可能需要转码
4. **HDR 素材（HLG/HDR10）自动色调映射为 SDR** — 预览与导出一致，在所有设备上稳定；V1 不导出 HDR。若设备 GL 管线异常，预览会自动降级到兼容模式（画面效果不显示，导出不受影响）
5. **自由裁剪** 通过边距滑杆实现（不是框选手势）
6. 文字内容编辑不进入撤销栈（样式调整会进）
7. debug APK 体积较大（~71MB，含全量图标与调试符号）；release 构建约 53MB
8. CompositionPlayer 为 Media3 实验性 API（`@UnstableApi`），升级 Media3 大版本时需回归测试
